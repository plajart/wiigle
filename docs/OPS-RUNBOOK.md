# 운영 점검·복구 절차서 (본사 관리모드 "운영 점검·복구")

대상: 본사(owner) 운영자, 움막AI(서버 운영). 더파티처럼 매장·포스기가 많은 고객사를 **한 매장부터** 실사용으로 도입할 때 쓴다.

## 0. 원칙

- 포인트는 챔프(포스) 결제의 적립·사용·취소와 포스 잔액의 서버 이전으로만 바뀐다.
- 문제가 생기면 **먼저 멈추고(긴급 스위치) → 원인을 보고(점검 화면·고객 조사) → 정정(되돌리기·보정)** 한다. 원장(PointEvent)은 지우거나 고치지 않고 반대 내역을 추가한다. 모든 조치는 사유와 함께 감사로그(`OPS_*`)에 남는다.
- 본사 관리모드 메뉴: **운영 점검·복구** (`/owner/ops`). 30초마다 자동 새로 고침.

## 1. 도입 순서 (한 매장 시범 → 확대)

1. **백업**: (움막AI) 도입 전에 `mongodump` 로 DB 전체 백업(아래 §6). 본사는 "운영 점검·복구 → 원장 내보내기"에서 계좌별 잔액 CSV 를 받아 둔다.
2. **매장 선정**: 포스기 대수가 적은 매장 1곳. 그 매장의 포스기 목록·각 포스기의 챔프 DB 가 **서로 복제돼 있는지**(같은 고객의 `MEM_USABLE_PNT` 가 포스기마다 같은지) 먼저 확인한다 — 복제돼 있으면 한 대만 이전하고 나머지는 보류 처리해야 한다.
3. **포스기 한 대씩 설치·초기 이전**: 첫 대 이전 후 본사 점검 화면에서 포스기 상태·이전 합계를 확인하고 다음 대로 넘어간다.
   - 두 번째 이후 포스기가 같은 고객을 비슷한 금액으로 이전하려 하면 서버는 **더하지 않고 보류**한다(`STORE_REPLICA_SUSPECT`). 점검 화면 "포스 포인트 이전 보류"에서 확인:
     - 같은 포인트의 복제 → **더하지 않음**(포스 잔액만 정리됨)
     - 포스기마다 따로 쌓인 포인트가 맞음 → **서버에 더함**
4. **대조**: 포스 바탕화면의 `포인트서버이전백업_*_initial_*.csv` 합계(전화번호 있는 회원만)와 서버 계좌 합계(원장 CSV)를 비교한다. 차이가 있으면 §3 의 "이전이 잘못됨".
5. **자동 반영은 처음엔 끈 채** 트레이 "포인트 사용…" 팝업만으로 1~2일 사용 → 이상 없으면 **한 대에서만** "고객 조회 시 통합포인트 자동 반영 (시험)" 체크를 켠다 → 이틀 정도 점검 후 같은 매장의 다른 포스기 → 다음 매장.
6. 다른 매장은 시범 매장이 안정될 때까지 설치하지 않는다(설치하면 이전이 시작됨).

## 2. 매일 점검 (시범 기간)

점검 화면에서 다음이 모두 0/정상인지 본다.

| 항목 | 의미 | 조치 |
|---|---|---|
| 이전 보류 | 중복 이전 의심 / 이전 기록보다 포스 잔액이 많음 | 승인(서버에 더함) 또는 기각(더하지 않음) — §3-2 |
| 마이너스 잔액 계좌 | 사용액이 잔액보다 커서 서버가 강제 차감 | 원인 확인 후 되돌리기·보정 — §3-3 |
| 잔액 부족 차감 | 위의 원인 결제 목록 | 동시 사용·중복 이전·오프라인 사용 여부 확인 |
| 서버가 거부·보류한 결제 | 전화번호 없음, 잘못된 값 | 회원 전화번호를 챔프에 등록하면 사후 처리 |
| 오래 남은 반영 | 포스에 반영해 둔 값이 20분 넘게 되돌려지지 않음 | 해당 포스 확인(꺼짐·오류), 다시 켜면 이어서 정리 |
| 걸려 있는 잠금 | 사용 조회 잠금이 남음 | "잠금 풀기" |
| 포스기 상태 | 끊김·구버전·미전송·오류 | 해당 포스 확인 |

## 3. 상황별 대응

### 3-1. 통합포인트가 이상하게 많거나 적게 보인다 / 원인 불명
1. **긴급 스위치**: "포인트 사용 일시 중지" 켬(모든 포스에서 사용 조회 거부, 적립은 계속) + 필요하면 "자동 반영" 멈춤. 최대 30초 안에 포스기에 전달된다.
2. 고객 조사(전화번호) → 계좌·최근 내역·포스↔서버 이동 기록을 시간순으로 본다.
3. 원인에 따라 §3-2~3-5. 끝나면 스위치를 되돌린다.

### 3-2. 이전이 잘못됨(복제 DB 를 포스기마다 중복 이전 등)
- 보류 단계에서 잡혔다면 "더하지 않음" 처리.
- 이미 서버에 더해졌다면: 고객 조사에서 해당 `초기 이전` 내역을 **되돌리기**(한 건), 또는 포스기 행의 **초기 이전 되돌리기**(그 포스기가 이전한 모든 내역을 한 번에, 미리보기로 건수·금액 확인).
- 서버만 되돌려지므로 포스의 잔액은 그대로 0이다. 포스 잔액을 복원해야 하면 포스에서 `restore-bulk-import-backup.ps1`(바탕화면 백업 파일 사용)을 실행한다 — 복원 전에 그 값을 서버로 다시 이전하지 않도록 주의(되돌린 포스기는 이전 기록이 없어 다음 이전 때 다시 더해진다).

### 3-3. 마이너스 잔액 / 잔액 부족 차감
- 챔프에서 확정된 결제라 되돌릴 수 없다. 원인(두 포스 동시 사용, 중복 이전 후 정정, 오프라인 사용)을 확인하고, 필요하면 **보정**(+)으로 0 에 맞추거나 고객·고객사 정책대로 처리한다. 보정은 사유 필수.

### 3-4. 챔프에서 사용했는데 서버가 안 줄어듦 / 적립이 안 올라감
- 포스기 행의 "미전송"·최근 오류 확인. 인터넷이 끊겼다면 연결 후 자동 반영(중복 없음, 거래별 고유키).
- 고객 조사의 이동 기록에서 `사용/적립 → 서버` 가 있는지 본다. 없고 포스가 정상이라면 포스 로그(`agent.log`)를 움막AI 에게 요청.

### 3-5. 잘못 입력한 내역 한 건
- 고객 조사 → 최근 내역 → **되돌리기**(사유 필수). 적립→적립 취소, 사용→사용 취소(환원), 그 밖은 조정 내역이 추가된다. 같은 내역은 한 번만 되돌릴 수 있다(DB 고유 인덱스).
- 이체 내역은 되돌릴 수 없다(고객 이체를 직접 정정).

### 3-6. 포스가 꺼지거나 프로그램이 재시작돼 값이 남음
- 프로그램은 반영 중인 손님을 `swap-state.json` 에 저장하므로 다시 켜지면 이어서 정리한다. 급하면 "잠금 풀기" + 포스 프로그램의 "포인트 서버로 이전"(남은 포인트 정리).

### 3-7. 자동 반영이 오작동
- 긴급 스위치로 자동 반영을 멈추면 트레이 팝업 방식으로 돌아간다. 포스별로는 트레이 체크 해제.

### 3-8. 큰 사고(여러 고객 잔액이 틀어짐)
1. 긴급 스위치로 사용 중지.
2. 원장 CSV(계좌·내역)를 받아 사고 전 CSV 와 대조, 범위 파악.
3. 범위가 작으면 되돌리기·보정. 범위가 크면 움막AI 에게 **DB 백업 복원**(§6)을 요청 — 복원 시점 이후의 정상 결제는 포스 큐(`CRAB_EVENT_QUEUE`)가 `PROCESSED='Y'` 라 자동 재반영되지 않으므로, 복원 후 해당 구간의 포스 결제를 별도 처리(원장 CSV·포스 이력 대조)해야 한다.

## 4. 포스 쪽 안전장치

- 이전 전 백업: 이전할 때마다 포스 바탕화면에 `포인트서버이전백업_*.csv`(최초 이전은 `_initial_`) 생성.
- 이전 멱등: (포스기, 이전 묶음, 전화번호, 금액) 이 같으면 한 번만 반영. 같은 포스기가 같은 고객을 다시 보내면 이미 이전한 만큼은 `alreadyApplied`(포스만 0으로 정리), 더 많으면 `held`(보류, 본사 확인).
- 결제 반영 멱등: 거래 키(`EARN-<포스>-<SEQ>`, `USE-…`)가 같으면 한 번만 반영. **`CRAB_EVENT_QUEUE` 테이블을 지우거나 재생성하지 말 것**(일련번호가 초기화돼 새 거래가 이전 거래로 오인돼 누락된다).
- 사용 조회 잠금: 조회 후 최대 600초, 사용 반영·되돌림 때 즉시 해제. 다른 포스는 그동안 적립만 가능.

## 5. 서버 쪽 API (참고)

- `GET /api/v1/owner/ops/review?companyId&storeId&hours` — 점검 데이터
- `GET /api/v1/owner/ops/customer?phone` — 고객 조사
- `POST /api/v1/owner/ops/actions` — `reverse-event`, `correct-balance`, `release-locks`, `resolve-hold`, `preview-terminal-imports`, `reverse-terminal-imports`
- `GET|PATCH /api/v1/owner/ops/switches` — 긴급 스위치(`autoInjectAllowed`, `redeemPaused`)
- `GET /api/v1/owner/ops/export?kind=accounts|events&days&companyId` — CSV
- 포스 에이전트: `POST /api/v1/pos/agent/redeem { action: "lookup" | "apply" | "cancel" | "release" }`, 하트비트 응답에 `autoInjectAllowed`, `redeemPaused`

## 6. 백업·복원 (움막AI)

```bash
# 백업(도입 전, 큰 변경 전, 매일 시범 종료 후)
mongodump --uri="$MONGODB_URI" --gzip --archive=/root/backups/pm-$(date +%Y%m%d-%H%M).archive.gz
# 복원(사고 시, 반드시 본사 승인 후 — 현재 DB 를 덮어쓴다)
mongorestore --uri="$MONGODB_URI" --gzip --archive=<백업파일> --drop
```
- `MONGODB_URI` 는 운영 환경 값(비밀값, 문서·채팅에 적지 않는다). DB 이름·접속 정보는 서버의 `.env.local`/파드 환경변수를 확인한다.
- 복원 전에 현재 상태도 한 번 더 백업해 둔다(되돌릴 길을 남긴다).
